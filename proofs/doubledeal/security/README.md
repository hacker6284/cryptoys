# DoubleDeal security theorems (draft)

Separate Lake package so the refinement package (`../lean`) and `Generated/`
stay dependency-free. Requires Mathlib `v4.14.0` (rev `4bbdccd9`, pinned in
`lake-manifest.json`, matching `leanprover/lean4:v4.14.0`) and `../lean` as a
path dependency.

```sh
lake exe cache get                  # prebuilt Mathlib; never build Mathlib from source
lake build
python3 ../check_axioms.py security # audits EVERY DoubleDealSecurity theorem
lake build DoubleDealSecurityHeavy AuditAll                   # heavy witnesses (five decide! encryptions, GridCycle survival checks, covariant-case checks); Lake may build several heavy modules (4.7-8.1 GiB peak RSS (CI, 5f2dc8f)) in parallel
python3 checks/heavy_rss.py                                    # what CI runs: the heavy modules one at a time, wall time and peak RSS per module; whole `doubledeal-security-heavy` CI job: 29m43s, measured once at 5f2dc8f (#170), largest step `GridCycleSurvival` 8.09 GiB peak RSS (then `RealKey` 6.35 GiB); a measurement, not a bound
python3 ../check_axioms.py security-heavy                      # audits EVERY heavy theorem
python3 checks/scan_sorry.py --selftest && python3 checks/scan_sorry.py  # no admit/native_decide/sorryAx/axiom; sorry only in the conjecture
python3 checks/selftest.py && python3 checks/check_relabel.py && python3 checks/check_covariant.py
```

## Layout

Two libraries: `DoubleDealSecurity` (the default target) and
`DoubleDealSecurityHeavy` (kernel witnesses taking minutes; not a default target,
so a plain `lake build` skips it). Most of the code is about relabellings
`σ : Equiv.Perm (Fin 52)` of card values. `BranchNumber` is separate: the
trivial branch-number floor on decks, and the GridCycle tail swap that attains it.

| Module | Content |
|---|---|
| `Decks` | named cards, witness decks, the cell-map interface |
| `Relabel` | relabellings, decks, commuting/covariance notions |
| `SumRanks` | **deprecated v8/v9 models.** Two-weight SumRanks commutes iff σ is a constant weight shift; v8 rank-preserving; the 52-element v9 group `v9Sym` |
| `SumRanksV10` | v10 SumRanks commutes with every `v10Sym a x` (rank + a mod 13, GF(4) suit label ⊕ x; 52 elements, ℤ/13 × (ℤ/2)², not cyclic): `sumRanksV10_commutes_v10Sym` ("if", on every card-valued grid) |
| `SumRanksV10Iff` | the converse and the full characterisation `sumRanksV10_commutes_iff`: σ commutes with v10 SumRanks on every deck iff σ = `v10Sym a x` for some a, x. Proof: the chained steps are one row rotation then one column rotation (`sumRanksChain_eq`); commuting on a deck forces equal amounts; two decks differing in the last card of row 0 force a constant rank shift mod 13, and two differing in the top card of column 1 force a constant suit-label shift. Like v9's `sumRanks_commutes_iff` |
| `StemPosition` | **the stem as a position map, and the support gap** (first slice of the off-diagonal stem column bound of the M7 row below; structure only, **no count of decks and no bound on `dpFCount` or any differential**). `unkeyedNoMix_eq_comp`: `unkeyedNoMix m = m ∘ stemPos m` for every packet, where `stemPos m k = cmFlat (seatMap (rowAmts m) (colAmts m) (inSeat k))` (`inSeat k`: the fixed SumRanks-output seat that ShiftRows and the column-major scoop send to position k; `seatMap`: one row rotation then one column rotation by the amounts v10 SumRanks uses on `m`, from `sumRanksChain_eq`; `srcRow` is the source row it reads); `stemPos_injective`. For a deck `x = permDeck π` with `unkeyedNoMix (β·x) = γ·unkeyedNoMix x`: `conj_of_stem_rel` `γ⁻¹ * β = π * (stemPerm x * (stemPerm (β·x))⁻¹) * π⁻¹` (`inSeat` cancels in the ratio, so only `cmFlat` conjugates the ratio of the two seat maps; prose, not a theorem). That hypothesis is exactly the filter predicate of `dpFCount β γ` (`FullCipher`; `Differential.dpCount`) at the deck `permDeck π`, the count in the off-diagonal stem bound (`StemUnion.dpFCount_le_of_ne`), and the one-deck form of "the stem is exactly covariant from β to γ". `card_fixed_eq` `γ⁻¹ * β` fixes exactly `zRows · zCols` cards (z = the number of agreeing rows / columns: rows whose row amounts agree mod 13 between `x` and `β·x`, times columns whose column amounts agree mod 4; `seatMap_eq_iff`, `card_seatMap_eq`: the agreeing seats are, per agreeing column, the agreeing rows shifted by that column's rotation, not literally the product set); `card_moved_eq` it moves `52 − zRows · zCols`; `card_moved_cases` so it moves 0 cards, exactly 4 with `(zRows, zCols) = (4, 12)`, or at least 8 (written `(γ⁻¹ * β).support.card`); `card_moved_zero_or_ge_four` (0 or at least 4) is its corollary (never 1 holds for every permutation; its content is never 2 or 3). `card_moved_eq` also excludes 9–11, 14, 15, 17, 18, 21, 23, 27, 29, 33 and 35, not stated. Alone this proves no part of the off-diagonal stem bound: it gives `dpFCount β γ = 0` only when the support size of `γ⁻¹β` is not of the form 52 − ab (a ≤ 4, b ≤ 13); for supports 1–3 and 5–7 that is `StemSupportFour.dpFCount_eq_zero_of_support_lt_eight_ne_four` (for the other excluded values it is not stated), and it says nothing for any other β. Which `(zRows, zCols)` occur for a given β is not studied. About the stem (final no-mix round) only |
| `StemCoupling` | **a coupling bound for decks with a prescribed conjugate and prescribed row amounts** (second slice towards the same bound; one counting lemma, **no bound on `dpFCount` or any differential, no part of the off-diagonal stem bound**). `rowAmts_eq_iff`: `StemPosition.rowAmts m = t` iff four row conditions hold, each reading one row (row ρ turned by `t ρ`, row 0 unturned, has v10 row total `t (ρ+1 mod 4)`). `card_hit_le_three`: at most 3 of the 8 subset sums of three nonzero residues mod 13 hit a target. `double_count`: involutions preserving `E`, at most `K` of them sending each point into `P`, give `\|G\| · #(E ∩ P) ≤ K · #E`. `card_cond_act_le`, `coupling`: for every `q δ` with `q` moving at most one position of each row and every `t`, `4096 · #{π \| π⁻¹δπ = q ∧ rowAmts (permDeck π) = t} ≤ 81 · #{π \| π⁻¹δπ = q}` (three swaps of free cards with different ranks per row, `(3/8)^4`). The support-4 shape of `q`, the conjugate counts and the assembly into `64 · dpFCount β γ ≤ 52!` are `StemSupportFour` (next row). The constants are sized in `analysis/v12-fullcipher/NOTES.md` §5 (enumeration, not proof). About the stem's SumRanks row amounts only |
| `StemSupportFour` | **the 4-card case of the off-diagonal stem bound** (third slice towards the same bound; one support size; supports ≥ 8 are `StemUnion`, next row). `qPerm t c d`: the permutation of positions sending `cmFlat ρ ((c + t ρ) % 13)` to the same seat of row `ρ + d` and fixing the rest; `qPerm_moves_le_one`: at most one moved position per row (`(movedInRow (qPerm t c d) ρ).card ≤ 1`). `ratio_eq_qPerm`: row amounts agreeing mod 13 and column amounts agreeing mod 4 except at column `c` make the ratio of the two position maps `qPerm (rowAmts m) c d`. Supports are `(γ⁻¹ * β).support.card` (Mathlib's `Equiv.Perm.support`). For `δ = γ⁻¹β` moving exactly 4 cards and a deck counted by `dpFCount β γ`: `ratio_eq_qPerm_of_support_four` the ratio `q` of `conj_of_stem_rel` is `qPerm (rowAmts x) c d` with `d ≠ 0` (so it is determined by `(rowAmts x, c, d)`), and `ratio_moves_le_one_of_support_four` it moves at most one position per row. `card_conjSet_le_odd`, `card_conjSet_le_two`: for `δ` of support 4, at most `4 · 48!` decks for `d = 1, 3` and `8 · 48!` for `d = 2` (upper bounds only); `sum_card_conjSet_le`: at most `8 · 48!` over the four `d` (`δ² = 1` allows only `d = 2`, `δ² ≠ 1` only `d = 1, 3`; no cycle types needed). `dpFCount_le_of_support_four`: **`64 · dpFCount β γ ≤ 52!` when `γ⁻¹β` moves exactly 4 cards** (from `dpFCount_bound_of_support_four`: `4096 · dpFCount β γ ≤ 81 · 13^5 · 8 · 48!`, about `0.00904 · 52!`, from `coupling` on each of the `13^5 · 4` cells). `dpFCount_eq_zero_of_support_lt_eight_ne_four`: supports 1–3 and 5–7 count no deck (`card_moved_cases`). About the stem (final no-mix round) only |
| `StemUnion` | **the support-≥ 8 case of the off-diagonal stem bound, and the column bound into γ outside `v10Sym`** (final slice of the same bound). `ratio_eq_ratioQ`, the general ratio formula: the ratio of two position maps is `ratioQ T T' E`, a function of the row amounts `T`, `T'` mod 13 and the column-amount differences `E` mod 4 only (`seatMap_shift`). `card_conjSet_le_reps`: for all `δ q`, `#{π \| π⁻¹δπ = q} ≤ s^⌊s/2⌋ · (52 − s)!` with `s = δ.support.card` (one representative per `q`-cycle: `reps`, `exists_rep`, `two_mul_card_reps_le`, with Mathlib's `Equiv.Perm.card_support_conj` and `conj_pow`; no centralizer lemmas). `card_agree_eq`: exactly `C(n, b) · (\|α\| − 1)^(n − b)` functions `Fin n → α` agree with a given one in exactly `b` places; `card_zR_eq`, `card_zC_eq`, `card_params`: for each `T`, `paramCount s` pairs `(T', E)` have `52 − zR · zC = s`. `paramCount_check` (`decide`, about a second, default library): `64 · 13^4 · paramCount s · s^⌊s/2⌋ · (52 − s)! ≤ 52!` for `8 ≤ s ≤ 52` (largest ratio ≈ 0.173, at s = 8). `mem_ratioCell` (through `zRows_eq_zR`, `zCols_eq_zC`), `dpFCount_le_union`, `dpFCount_le_of_support_ge_eight`: **`64 · dpFCount β γ ≤ 52!` when `γ⁻¹β` moves at least 8 cards**. `dpFCount_le_of_ne`: the same for every `β ≠ γ` (no `v10Sym` condition); `dpFCount_col_le_64`: the column bound `64 · dpFCount β γ ≤ 52!` for every `β ≠ 1` when γ is outside `v10Sym` (the diagonal is `FullCipher.dpFCount_self_le_64`). `fullDiffCount_le_64`: **`64 · fullDiffCount α γ n y ≤ (52!)^(n+2)` for every `α ≠ 1`, every γ outside `v10Sym`, every n and every deck y, with no hypothesis** (from `fullDiffCount_le_of_col`; independent uniform keys; the same 1/64 for every n (the bound does not decay; nothing is proved about decay)). Not for γ in `v10Sym` (`not_col_v10Sym`: this route gives nothing there); not the roadmap's one-round mix bound B1 (`dp1_le`); nothing for the real schedule. Not a security claim. About the final no-mix round's stem, through `FullCipher`'s Markov reduction |
| `OneRoundDP` | **the one-round mix bound B1 (`dp1_le`) on the 51 `v10Sym` rows, and what a bound on the other rows would imply** ([`../analysis/v12-dp1/NOTES.md`](../analysis/v12-dp1/NOTES.md)). `DP1Bound p` (a statement, not proved): `p · dp1Count α β ≤ 52!` for every α ≠ 1 and β (`Differential.dp1Count`: one mix round, the stem then GridCycle, independent uniform key). `covariant_iff_id_of_dp1_lt`, `covariant_iff_id_of_dp1Bound` (p ≥ 2): **any one-round bound below 1 implies the open covariant conjecture `roundBody_covariant_iff_id`** (a covariant pair counts every deck, `dp1Count_eq_of_covPair`); since the `v10Sym` rows are bounded, a bound below 1 on the rows OUTSIDE `v10Sym` alone already implies it (`covariant_iff_id_of_dp1_lt_off_v10Sym`), so those rows are not proved. For the `v10Sym` rows the stem passes the difference unchanged, and `mixRound_v10Sym_reads` reads GridCycle's first two seats on the output (seat 26 through `Differential.v10Sym_step_agree`; the second card's seat `seat2Idx`, `mixColumns_seat2`); with `card_seat_link_le` (three distinct seats of a uniform deck), `card_agree_le_fifty` and the GridCycle survival bounds, `dp1Count_v10Sym_le_sum` refines D4 (`Differential.dp1Count_v10Sym_le_agree`): `dp1_le_v10Sym` **`52 · dp1Count (v10Sym a x) β ≤ 52!` for every β, (a, x) ∉ {(0, 0), (0, 3)}**; `dp1_le_v10Sym_zero_three` `17 ·` for `v10Sym 0 3` (a limit of the two-seat argument: when the first card is K♣ or K♠ the two reads coincide, `sameSeat2`); `dp1_le_v10Sym_all` `17 ·` for all 51. Default library, a few seconds. Not B1 (rows outside `v10Sym` are open); one round only; independent uniform key; nothing for the real schedule. Not a security claim |

  under its library directory (`DoubleDealSecurity/` here, `DoubleDealSecurityHeavy/`
  in the heavy mode) was not loaded by the environment, since the audit never saw
  it; any Lean error fails `check_axioms.py`. Lean decides what is imported, so
  commented-out imports cannot fool it. A private and a public theorem with the same user name also fail.
  The audit also raises `DUP n` for any non-private name declared under its root that
  more than one module declares, including an identical redeclaration of a Mathlib or
  core name (Lean 4.14 merges identical imported theorems silently). Reserved
  (auto-generated) names are skipped. `checks/audit_dup_selftest.py` (CI) builds
  throwaway modules (in a temporary copy of the packages, not the source tree) and requires exactly two DUPs (an identical `isDeck_mixColumns`, and
  a user-declared `zfxH.eq_1`) and none for the on-demand reserved `zfxF.eq_unfold` /
  `zfxF.induct`.

CI ([`proofs-heavy.yml`](../../../.github/workflows/proofs-heavy.yml), job `doubledeal-security-heavy`) builds the heavy library
one module at a time (`checks/heavy_rss.py`; the per-module wall time and peak RSS are
in the job summary and log) and runs `../check_axioms.py security-heavy` (same rules, no KNOWN_SORRY; every
registered theorem must be reported) plus `scan_sorry.py`. It also audits the
Lean-generated theorems (e.g. equation lemmas) of the heavy modules, pinned in
`HEAVY_GENERATED`; see the comment at `HEAVY_THEOREMS` in `../check_axioms.py`.
When it runs: see that workflow.

Both jobs (`doubledeal-security` and `doubledeal-security-heavy`) must be green
before merge (not enforced by branch protection): each audit checks only its own
library, so a stray module can fail just one of them.

So any new sorry, and any new theorem built on the conjecture, fails CI. A
green run means the theorems check as stated; it is not a security claim.
Link 1 (sudo = Generated) remains open.

## Notes

  `encrypt`) takes about 50–80 s depending on the machine. Keep it `decide!`: do not switch it to
  `native_decide`, which would add `Lean.ofReduceBool` to the trusted base
  (and the gate rejects it).

  `measure_v9sym.log` (minutes; measurement only; v9).
